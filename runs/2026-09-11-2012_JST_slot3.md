  created_at: Thu, 10 Sep 2026 23:37:09 GMT
- url: https://x.com/hillbig/status/2098193798727909780
  id: 2098193798727909780

  text: DeepSeek-V4.1-Flashは、Long-horizonエージェント向けに多くの改良が施されたモデルである。

552BパラメータのMoEであり、Prefill時には約8B、Decode時には16Bパラメータをアクティブにする。さらにEngramとして196Bパラメータを持ち、Transformer本体は40層からなる。長い入力のPrefillでは主に下半分の20層を使い、Decode時には40層全体を使う。

特に大きく変わったのが、KVキャッシュをどのように生成・保存・再利用するかである。Causal Encoder-Decoder（CED）を採用し、AttentionにはSliding Window Attention（SWA）とCompressed Sparse Attention 2（CSA2）を組み合わせている。

マルチモーダルにもネイティブに対応、Vision Encoderは独自のDeepSeek-ViTを学習しており、2D RoPEやlinear projectionを採用する。
Patch EmbeddingをConvolutionではなくlinear projectionにしている理由の一つとして、Muon optimizerとの整合性が挙げている。またMoEのロードバランシングでは、テキストtokenと画像tokenで別々の補正バイアスを持たせている。

アーキテクチャとして今回の目玉が、Causal Encoder-Decoder（CED）の採用である。

Long-horizonエージェントでは入力コンテキストが非常に長くなり、Prefillの計算コストが大きな問題になる。CEDは20層のCausal Encoderと20層のDecoderから構成され、Encoder最終層の隠れ状態からDecoder各層のglobal KVを直接生成する。

つまり、Decoder各層のglobal KVを作るために、長い入力tokenをDecoderの20層すべてに通すさず、長いコンテキストではPrefill計算量をほぼ半分にできる。

ただし、Sliding Window AttentionのKVは各Decoder layer固有であるため、Decode開始時にはその状態を再構成する必要がある。
このとき、SWAの窓幅は128 tokenだが、層をまたいで依存関係が伝播するため、状態を厳密に復元しようとすると、本来は窓幅×層数に相当する範囲をReplayする必要がある。そこでSWA Bounded Replayでは、全層について最近の128 tokenだけをReplayして近似的に状態を復元する。実験上、この近似による性能低下はほとんどなかったという（実用上、再現ができないとかの問題はでるかも）

KVキャッシュは、現在Decodeしているリクエストが利用するruntime KVと、prefix reuseのために長期間保存するpersistent KVに分けられる。後者はSSDやホストメモリに保存される。
また、SWA KVをpersistent KV cacheには保存しない。SWA KVは短時間だけホストDRAM上に保持し、cache missした場合にはSWA Bounded Replayによってtoken列から再構成する。これによりpersistent KV cacheの容量を大きく削減している。

またCSA2では、KVキャッシュの圧縮について、これまで進められてきた特徴次元方向の圧縮（MQA、GQA、MLA）や系列方向の圧縮（複数tokenをまとめて圧縮）に加えて、層方向の圧縮に取り組んでいる。
具体的には、CSA2にはFull、Reindex、Reuseという3種類のモードがある。
Full Modeでは、その層自身がMain KVとIndexer Q/Kを生成し、Top-K indicesを新たに計算する。
Reindex Modeでは、Main KVとIndexer Kを前の層から再利用する一方、その層自身のIndexer Qを使って再度スコアリングし、新しいTop-K indicesを選択する。
Reuse Modeでは、Main KVだけでなくTop-K indicesも前の層から再利用し、Indexerによる検索自体を省略する。
なお、いずれのモードでも各層固有のMain QとSWA KVは計算する。

さらにDecoderではHierarchical Sparse Indexerを使う。最初のFull layerだけが全コンテキストを検索し、8 tokenを1 blockとして最大2,048 blockを選択する。これにより、
8 × 2,048 = 16,384 token
のcandidate poolを作った上で、それ以降のReindex layerでは、100万token全体ではなく、この約16K tokenだけを検索対象とし、最終的にTop-512のKVを選択してAttentionを行う。

したがって、
1M token → 約16K candidate → Top-512
という二段階のsparse retrievalになっている。

mHCについても推論効率化が行われている。従来のmHCでは、その層のresidual streamから入力混合係数 A_l を計算してから同じ層の入力混合に使っていたため、処理間に依存関係があり、activationを複数回読み出す必要があった。
Single-Pass mHCでは、この入力混合に一つ前のblockで計算した係数 A_{l-1} を使うように変更する。これによって依存関係を解消し、residual update、input mixing、coefficient predictionなどを1つのfused kernelで処理できる。性能低下はほとんどなく、activation memory trafficを大きく削減できる。

またDeepSeek-V3で使われていたMTPはbackboneの事前学習には使用せず、backbone pre-training終了後にDSparkというspeculative decoding moduleを別途学習する。DSparkでは1回のforwardで5つのdraft positionを並列に予測し、confidenceに応じて何tokenまでまとめてverifyするかを動的に決める。

事前学習もいろいろ書かれている中で注目されるのは、batch sizeが約100M tokenと非常に大きいこと。また、Dense Attentionから徐々にSparse Attentionへ移行するのではなく、最初から64K contextのSparse Attentionでfrom scratch学習している。34T tokenの時点でcontext lengthを1M tokenまで拡張している。

コメント
===
Long-horizonエージェントを効率的に実行するための工夫を、モデルアーキテクチャからKVキャッシュ、推論システムまで広範囲に取り入れたモデルである。これらの工夫は推論だけでなく、長いtrajectoryを大量に生成するRLやPretrain学習時にも大きな恩恵がある。

PrefillをEncoderとDecoderに分離する考え方自体はYoCoなどですでに提案されていたが、それがこの規模の実用モデルに搭載され、再注目されるきっかけとなるのではないか。

また、すべての状態をGPUのHBMに保持するのではなく、用途に応じてホストメモリやSSDを積極的に利用する設計思想は徹底しており、パラメータについてはEngramをホストメモリからprefetchし、KVキャッシュについても長期保存が必要なglobal KVと、短時間しか再利用されないSWA KVを分離して管理している。

一方で、このTechnical Reportには十分なAblationがなく、どの設計がどの程度性能や効率に寄与しているのか、またどのようなトレードオフのもとで他の選択肢から現在の構成を選んだのかは十分には分からない。
それでも、これらの採用した方針は今後の大規模モデル開発に影響を与えるだろう。
